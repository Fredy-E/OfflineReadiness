05Download the report

Redacted by default. The opt-in adds original names and identifiers — never secrets. Manufacturer/model and known source enums stay as product metadata; review before sharing.

Reports are redacted by default: names and identifiers are ordinalized (Entry C01, Entity E01, Device D01) and arbitrary source labels are omitted. Known Home Assistant source enums (user, discovery, …) and device manufacturer/model remain as product/acquisition metadata — review them before sharing. The opt-in includes the original names and identifiers from the normalized state — never secrets: credential-bearing config entry data/options and device connection/serial/URL fields are discarded at import and can never appear in any report.

Supported inputs, limits & honest limitations

Supported input

  • Normalized snapshot — one JSON file with schema offline-readiness.snapshot/1: haVersion plus allowlisted entries, entities and devices arrays (see docs/snapshot-contract.md).
  • Registry bundle — the three Home Assistant .storage exports selected together in one multi-file pick: core.config_entries, core.entity_registry, core.device_registry. config_entries and entity_registry are always required; the device registry is required when entities reference devices. New single config_entry_id devices and legacy config_entries arrays are both accepted. A valid export may contain zero records (a fresh home) and still join; only an import whose exports together hold no records at all is refused with EMPTY_INPUT.
  • Allowlisted fields only. Config entry data/options/subentries, device connections/serial_number/configuration_url/identifiers, entity unique_id/capabilities/labels and all unknown fields are discarded before state creation — counts are shown, values never survive.

Not supported (explicit errors, never guessed)

  • Full or encrypted Home Assistant backups, archives (.zip, .tar, .gz), YAML files (configuration.yaml, automations.yaml) and automations/scripts.
  • Dynamic templates and template entities are never evaluated; template/group platforms are reported as unknown with an explicit dynamic-platform note.
  • Nothing is fetched from Home Assistant: no server, no supervisor, no live state.

Limits

  • 8 MiB per file, 8 files per import; 5,000 entries / 20,000 entities / 10,000 devices (fail closed with a visible error).
  • Display strings are capped at 200 characters (truncations are counted); devices keep at most 32 config-entry references; at most 500 issues are listed while totals stay complete.
  • Bundled classification evidence is dated 2026-10-11 (home-assistant/core tag 2026.10.1); evidence older than 180 days is flagged stale.

Honest limitations

  • This is a dependency evidence report, not a whole-house offline-safe certification, and there is no aggregate score.
  • “Local” is the integration’s declared communication model; firmware updates, companion apps, accounts and cloud features are out of scope.
  • MQTT entities talk to a user-configured broker whose locality cannot be verified here, so MQTT is reported as unknown.
  • Domains outside the bundled evidence set are reported as custom/unlisted — never assumed local.
  • Bundled evidence is tied to the dated tag above; the imported Home Assistant version is displayed for context and never compared against it — a version mismatch is not automatically flagged.
  • Registry version/minor_version fields are tolerated, not certified: the adapters match on key/shape, and the versions listed in the contract describe the live storage format only.
  • Classification is a domain-name lookup against the named core manifests. A custom integration that shadows a bundled domain (for example a custom “hue” fork) still shows the bundled evidence — installed code is never inspected.
  • Device via references are direct links only; cycles are not detected and references are not resolved transitively.
  • Device manufacturer/model and known source enums stay in redacted reports as product/acquisition metadata — review them before sharing.
  • Physical device behavior and runtime offline operation were not tested.
